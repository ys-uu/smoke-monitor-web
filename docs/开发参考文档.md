## 1 项目简介与技术栈

系统逐帧检测人脸周边的香烟，支持按当前帧或按跟踪 ID 进行多帧投票报警，并自动保存事件级违规记录。

| 层 | 技术选型 | 说明 |
|---|---|---|
| 浏览器前端 | 原生 HTML / CSS / JavaScript | 无 Node 构建链；第三方资源放 `webapp/static/vendor/` 本地化，禁止公网 CDN |
| 后端服务 | Flask 3.1、Flask-SQLAlchemy | 提供 JSON API、MJPEG 流、静态页面托管 |
| AI 推理 | Ultralytics YOLOv8、BoT-SORT | 定位并跟踪人脸，再在局部检测香烟。两个 YOLO 模型有 CUDA 时优先使用 GPU |
| 数据库 | MySQL 8.0（Docker 容器） | 独立容器、独立命名卷；保留手动 SQLite 应急连接 |

## 2 团队分工与模块边界

### 2.1 角色分工

| 角色 | 负责范围 | 主要工作目录 | 对应任务 |
|---|---|---|---|
| 前端开发 | 页面结构、样式、MJPEG 渲染、状态轮询、记录页交互 | `webapp/templates/`、`webapp/static/` | T3-4、T4-3 |
| 后端开发 | 路由蓝图、视频源解析、会话管理、事件接口 | `webapp/blueprints/`、`webapp/services/` | T3-1~3、T4-1~2 |
| 推理引擎 | 检测、投票、绘制、引擎单例与自检（主体已完成） | `webapp/services/infer_engine.py`、`engine_holder.py` | 已交付 |
| 模型训练 | 数据集、训练、评估、权重回传 | 独立训练工程 | 模型负责人 |
| 数据与文档 | ORM、表结构、测试、文档维护 | `webapp/models.py`、`deploy/mysql/`、`docs/` | 全员配合 |

### 2.2 模块边界约定

- 前端只通过 `/api/*` 与后端通信，不直接加载模型、不直连数据库。
- 推理引擎不读摄像头、不写文件、不碰数据库，只接收帧并返回标注帧 JPEG 与 info 字典，可独立单测。
- 数据库访问统一走 Flask-SQLAlchemy ORM，业务代码不写数据库专有 SQL。
- 所有环境差异收敛到 `.env` 与 `config.py`，代码内不写死个人路径与个人环境信息。
- 推理逻辑全工程只维护一份，禁止出现两套检测/投票实现。

### 3.2 获取代码与安装依赖

```powershell
cd smoke-monitor-web
pip install -r requirements-web.txt
```

### 3.3 本地启动（5 步）

1. 准备环境变量：`Copy-Item deploy/mysql/.env.example deploy/mysql/.env`，按需修改。

5. 浏览器访问 `http://127.0.0.1:8010`，在“关于与部署”页执行模型引擎自检。

> 工程关闭了调试自动重载（`debug=False`），修改后端代码后需停止并重新执行 `python run_web.py`。

## 5 页面详细设计

### 5.1 整体布局

- 顶部栏：系统名、当前权重、数据库驱动徽标、视频源状态灯、当前时间。
- 标签导航：P0 实现“实时监控 / 违规记录”两个页签；P1 页签预留或隐藏，不做不可用入口。
- 主色为橙色（CSS 变量 `--brand`），视频区深色；投影场景正文不小于 14px，关键状态 16px 以上。

### 5.2 实时监控页 · 视频源区

分段单选，同一时刻仅一个会话；四种来源：

| 来源 | source_type | 行为与字段 |
|---|---|---|
| 样例视频 | sample | 下拉扫描样例目录白名单视频，显示文件名与大小，默认选中主样例 |
| 本机路径 | local | 文本框粘贴绝对/相对路径，调校验接口；成功显示宽高、fps、时长，失败给中文原因 |
| 上传视频 | upload | 单文件选择 + 拖拽，带进度条；后端 uuid 落盘，成功后自动选为待开始源 |
| 摄像头 | camera | 设备号输入，默认 0；不做自动枚举；网络流入口禁用并标注 P2 |

关键约束：开始会话时后端再次解析校验，不信任前端上次结果；标准浏览器拿不到文件真实绝对路径（fakepath），路径直读与上传两个入口分别覆盖“零拷贝”和“任意位置”诉求。

### 5.3 实时监控页 · 参数面板

开始前一次性配置，运行中锁定。后端统一做类型转换、范围校验与归一化，响应回传最终生效值。

| 控件 | 字段 | 默认值 | 取值范围 |
|---|---|---|---|
| 置信度滑块 | conf | 0.35 | 0.05–0.95 |
| NMS IoU 滑块 | iou | 0.70 | 0.10–0.90 |
| 按跟踪 ID 投票 | use_vote | 关 | 开/关 |
| 投票窗口 | vote_window | 1 | 1–15 |
| 投票阈值 | vote_threshold | 1 | 1–窗口值 |
| 香烟推理分辨率 | imgsz | 960 | 320/480/640/960 |
| 事件冷却 | event_cooldown_sec | 10 | 5–300 |
| 心跳开关 | heartbeat | 开 | 开/关 |
| 快照开关 | save_snapshot | 开 | 开/关 |
| 循环播放 | loop | 关 | 开/关（仅文件源） |

### 5.4 画面卡与状态卡

- 画面卡：MJPEG 图像自适应宽度、保持源比例；未开始显示深色占位；ALARM 时页面红色横幅与画面红底角标双保险。
- 文件播放结束：未循环则进入 ended 并保留最后一帧，提示可重新开始；循环则重新打开文件。
- 状态卡（1s 轮询）字段：运行状态 idle/starting/running/ended/error、来源类型与展示名、FPS（EMA）、推理 ms、帧号、视频时间、烟框数、投票 sum/window、conf/iou/imgsz、会话 ALARM 次数、最近事件时间、模型名、数据库驱动、错误信息。

### 5.5 违规记录页

- 筛选栏：日期范围、视频源、状态（全部/未处理/确认/误报）、每页条数（12/24/48）；按钮：查询、重置、导出 CSV、刷新。
- 卡片墙：快照缩略图、事件时间、源名称、最高 conf、投票 sum/window、状态徽标、模型名、记录原因；点击打开大图。
- 详情 Modal：大图、bbox 坐标、帧号/视频时间、墙钟时间、快照路径、备注；操作含标记、删除（二次确认）、下载原图。
- 分页：总数、页码、上下页、跳页；空态给出引导提示。

## 6 数据库设计

### 6.1 表结构摘要

核心表 `detection_event`（18 列），完整 DDL 见 `deploy/mysql/initdb/schema.sql`。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INT 自增主键 | 主键 |
| event_time | DATETIME(6) | 报警墙钟时间 |
| source_id / source_type | VARCHAR | 来源标识与类型（sample/local/upload/camera） |
| source_name | VARCHAR(255) | 来源展示名 |
| frame_index / video_time_sec | INT / FLOAT | 文件源帧号与视频内时间，实时流可空 |
| max_conf | FLOAT | 最高香烟置信度 |
| vote_sum / vote_window | INT | 记录时票数与窗口 |
| model_name | VARCHAR(128) | 权重文件名，支持追溯 |
| snapshot_relpath | VARCHAR(512) | 快照相对路径，不存图片二进制 |
| bbox_json | TEXT | 烟框坐标与置信度 JSON |
| status | VARCHAR(16) | open / confirmed / false_alarm |
| reason | VARCHAR(16) | alarm_start / heartbeat |
| note | VARCHAR(255) | 人工备注，可空 |
| created_at | DATETIME(6) | 入库时间 |

索引：`idx_event_time(event_time)`、`idx_source_time(source_id, event_time)`、`idx_status(status)`。

### 6.2 建表方式

- 默认：应用启动时 `db.create_all()` 自动建表。
- 手动：执行 `deploy/mysql/initdb/schema.sql`，或挂载到容器 `/docker-entrypoint-initdb.d/` 由首次初始化执行。

### 6.3 文件布局

- 事件快照：`data/web_events/日期/uuid.jpg`，与实时画面同源的标注 JPG。
- 上传文件：`data/web_uploads/日期/uuid<扩展名>`，uuid 命名防穿越，原始文件名仅作展示映射。
- 删除事件时先删数据库行再尝试删除快照，避免孤儿数据库记录。

## 7 推理引擎与调用方式

### 7.1 引擎接口

引擎位于 `webapp/services/infer_engine.py`，主要对象：

- `InferParams`：会话参数数据类，含 `validate()` 范围校验与 `to_dict()`。
- `VoteState`：管理会话内的跟踪器与独立的 ID 投票窗口。
- `InferEngine`：构造时加载并预热两个 YOLO 模型。`process_frame(frame, state, draw=True)` 返回 `(jpeg_bytes, info)`。
- `new_vote_state(params)`：每个会话、切换视频源或重新循环时创建独立的跟踪与投票状态。

### 7.2 会话调用示例

```python
from webapp.services.infer_engine import InferEngine, InferParams, new_vote_state

params = InferParams(weights_path=权重绝对路径, device="auto", imgsz=960,
                     conf=0.35, iou=0.70, use_vote=False)
engine = InferEngine(params)          # 仅加载一次
state = new_vote_state(params)       # 每个新会话各建一份
jpeg, info = engine.process_frame(frame, state)
```

### 7.3 info 字段

| 字段 | 含义 |
|---|---|
| frame_index | 帧序号（从 1 起） |
| face_count | 第一阶段检出的人脸数 |
| cig_count | 当前帧烟框数 |
| max_conf | 最高香烟置信度 |
| infer_ms | 人脸定位、局部香烟推理和框合并的耗时（毫秒） |
| fps_ema | 帧率指数平滑值 |
| device | 设备描述 |
| vote_sum / vote_window | 当前人员中的最高票数与窗口 |
| alarm_persons | 本帧报警人数 |
| is_alarm | 是否报警 |
| boxes | 烟框列表，每项含 xyxy、conf、cls_name |

### 7.4 投票与绘制口径

- 第一阶段以 640 推理尺寸和 `0.35` 置信度检测人脸，BoT-SORT 维护会话内跟踪 ID。人脸框四边各按脸宽或脸高向外扩展 `30%`，并裁剪到原帧边界。
- 第二阶段用 `smoke_cig_clean_n960_e100_best.pt` 逐个检测扩展区域。烟框映射回原帧后，以 `0.40` IoU 做跨区域去重，再按烟框中心是否位于某个搜索区域判断该人员是否检出香烟。
- 默认按单帧结果报警。启用投票时，各跟踪 ID 独立累计，离开画面后清除票数。报警且当帧有烟框、满足冷却条件时写入事件。
- 灰色表示搜索区域，橙色表示香烟框，绿色和红色分别表示未报警和报警的人脸。HUD 包含两阶段检测数、报警人数和 `SMOKING ALARM`。

## 8 API 契约（字段级）

### 8.1 通用约定

- 除 MJPEG 流与 CSV 下载外，统一 JSON 信封：

```json
{ "code": 0, "msg": "ok", "data": {} }
```

成功 `code=0`；业务错误 `code!=0` 且配合 4xx/5xx，`msg` 为可展示中文。
- 时间字段统一本地时间字符串；分页 `page` 从 1 开始。
- 全部接口仅监听 `127.0.0.1`；快照与上传文件经受控路由提供，禁止目录穿越。

以下为原单阶段引擎的离线回归数据。当前双阶段的实际帧率随硬件、帧尺寸和同一帧的人脸数量变化，可通过 `scripts/regress_engine.py` 复测。

## 11 通用故障排查

| 现象 | 排查方向 |
|---|---|
| 启动报端口占用 / 冲突 | 修改 `.env` 的 `WEB_PORT` 或 `SMOKE_MYSQL_HOST_PORT`，同步连接串端口后重启 |
| 数据库连接失败、health 报错 | 确认 Docker 引擎已启动、容器 running；检查 `.env` 端口与账号 |
| 摄像头打不开 | 确认设备号正确、未被占用；Windows 下可尝试 DShow 方式 |
| 视频文件无法播放 | 核对扩展名白名单与编码；先用路径校验接口探测 |
| GPU 未生效 | 检查驱动与 CUDA；或显式设置 `SMOKE_INFER_DEVICE`，CPU 功能完整 |
| 改代码后接口无变化 | 重启 `python run_web.py`，工程不启用自动重载 |

## 12 代码风格与协作约定

### 12.1 代码风格

- 命名语义化，Python 标识符小写加下划线；配置常量集中在 `config.py` 顶部。
- 关键逻辑加中文注释，保持扁平结构，避免无必要的过度封装与重复实现。
- 可复用逻辑统一放 `webapp/services/`，一次性临时脚本用完即删，不散落工程目录。

### 12.2 Git 协作

- `.env`、`instance/`、运行产物目录不提交，规则见 `.gitignore`；提交配置只使用 `.env.example`。
- 建议 `main` 保持可运行，各任务在独立分支开发后合并，合并前保证本地启动与自检通过。
- 提交信息简明，如“新增会话启动接口”“修复投票状态更新”。
